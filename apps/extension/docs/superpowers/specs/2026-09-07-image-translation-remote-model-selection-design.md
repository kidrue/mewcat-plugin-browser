# 图片翻译独立选择远程视觉模型设计

## 状态

- 日期：2026-09-07
- 状态：已由用户确认
- 范围：图片翻译设置、模型发现、配置迁移、后台模型解析与缓存隔离

## 背景

当前图片设置把 `aiModelList` 中的 `BaseModel` 同时当作平台凭据和视觉模型。平台下拉按 `BaseModel.type` 去重，视觉模型下拉却显示 `BaseModel.name`。新增翻译服务时 `BaseModel.name` 默认就是平台名称，因此会出现“模型平台是阿里百炼，视觉模型仍是百炼”的重复展示。

用户期望第一层从“翻译服务”中已添加的配置选择一套平台凭据，再使用该配置的 API Key、官方或自定义请求地址获取平台的全部可用模型，第二层独立选择具体视觉模型。图片选择不得修改文本翻译当前服务或该服务原有的文本模型。

## 目标

1. 第一层选择翻译服务中已添加的具体平台配置实例，而不是只选择平台枚举。
2. 第二层通过所选配置动态发现模型，并展示真实模型名称和模型 ID。
3. 图片模型与文本模型独立保存；选择图片模型不得修改 `currentModel` 或 `BaseModel.params.modelName`。
4. API Key 和请求地址只从扩展配置中解析，不发送到网页上下文。
5. 老版本的图片模型配置自动迁移，升级后无需重新选择即可继续使用。
6. 图片缓存同时区分平台配置和具体模型，避免切换视觉模型后命中旧结果。

## 非目标

- 不把发现到的视觉模型自动添加到翻译服务列表。
- 不允许图片设置新建、删除或编辑平台凭据；凭据仍统一在“翻译服务”维护。
- 不改变网页文本翻译的服务选择逻辑。
- 不修改 Canvas Hook、IndexedDB 或缓存 schema 的独立版本语义。

## 方案选择

### 采用：平台配置 ID + 独立视觉模型名

保留 `imageTranslationModelId` 作为所选 `BaseModel.id`，它负责定位平台、API Key、请求地址和官方/自定义模式；新增 `imageTranslationModelName` 保存图片翻译实际传给 API 的模型标识符。

这一方案复用现有凭据和模型发现能力，只增加一个字符串配置，不复制敏感信息，也不污染文本翻译模型列表。

### 不采用：自动创建视觉模型服务条目

每次选择远程视觉模型都向 `aiModelList` 添加条目，可以复用现有后台链路，但会让仅供图片使用的模型出现在文本翻译服务中，并使删除、启用和排序语义混乱。

### 不采用：请求携带凭据快照

让图片请求直接携带 API Key、baseUrl 和模型名可以减少后台配置解析，但会扩大敏感信息的传播范围，也会造成配置重复和过期快照问题。

## 用户界面

### 平台配置

“模型平台”调整为“平台配置”。候选项来自 `aiModelList` 中已启用、API Key 非空且属于 LLM 平台的配置实例。Google Translate、Microsoft Translate、DeepL 等非 LLM 翻译引擎不进入列表。

每个选项显示：

```text
平台名称 · 当前文本模型 · 官方/自定义
```

例如：

```text
阿里百炼 · qwen-plus · 官方
阿里百炼 · qwen-turbo · 自定义
```

同平台、同模型、同模式的重复配置按出现顺序附加编号，不展示或截取 API Key。

切换平台配置时清空 `imageTranslationModelName`，终止过期的模型发现请求，并重新获取模型目录。系统不自动选择第一项，避免在用户未确认具体模型时启用图片翻译。

### 视觉模型

模型目录复用现有 `discoverModels()`：

- `vision === "supported"`：展示并标注“支持图片”。
- `vision === "unknown"`：展示并标注“图片能力未知”，允许通过“测试视觉能力”验证。
- `vision === "unsupported"`：明确仅支持文本，不出现在视觉模型候选中。
- 自定义接口不支持模型发现：降级为手动填写模型名，并显示原因。
- 网络或认证失败：保留重试入口，显示安全错误信息，不回显 API Key、完整请求头或响应体。

选项标签同时展示模型名称和实际模型 ID；两者相同时只显示一次。

## 配置与迁移

`ExtensionConfig` 新增：

```ts
imageTranslationModelName?: string
```

`imageTranslationModelId` 继续保存平台配置的 `BaseModel.id`，避免无意义的字段重命名和协议迁移。

配置修复规则：

1. `imageTranslationModelId` 能匹配现有 `BaseModel`，但 `imageTranslationModelName` 为空时，使用该配置当前的 `params.modelName` 补齐，兼容老版本。
2. 平台配置不存在、被禁用或 API Key 为空时，清空图片平台配置和视觉模型，并关闭图片快捷翻译按钮。
3. `imageTranslationModelName` 保留为普通字符串，不强制要求仍出现在远程目录中；平台可能临时无法返回模型列表，用户仍可通过能力测试验证已保存模型。
4. 配置继续写入当前 `sync:extension-config`；不额外保存 API Key 或模型目录副本。

## 模型发现复用

从现有 `ModelDiscoveryField` 中抽取可复用的模型发现状态逻辑，统一管理防抖、取消、刷新、加载、错误及自定义接口手动输入降级。文本翻译模型字段和图片视觉模型字段分别消费该逻辑，但拥有独立的筛选和写入行为。

模型发现只在扩展设置页执行。切换配置或组件卸载时通过 `AbortController` 取消旧请求；请求晚返回时不得覆盖当前配置的候选项或提示状态。

## 后台执行与安全边界

内容脚本继续只发送所选平台配置 ID，不发送 API Key、baseUrl 或模型目录结果。后台加载 `sync:extension-config` 后执行以下步骤：

1. 校验请求中的配置 ID 与当前 `imageTranslationModelId` 一致。
2. 从 `aiModelList` 查找该配置，校验它已启用且 API Key 非空。
3. 读取受信任配置中的 `imageTranslationModelName`；为空则返回“未选择视觉模型”。
4. 在内存中复制 `BaseModel`，只把副本的 `params.modelName` 替换为所选视觉模型名。
5. 使用副本调用现有视觉模型网关，不回写 `aiModelList`。

当前图片后台仍读取旧的 `local:extension-config`，本次同步改为 `sync:extension-config`，与 Jotai 配置适配器保持一致。

能力未知或手动填写的模型允许发起真实能力测试。平台明确返回不支持图片、响应结构无效或请求失败时，继续映射为现有安全错误码，不向页面暴露提供商原始错误详情。

## 缓存与并发

缓存和请求去重键必须包含：

```text
图片哈希 + 目标语言 + 平台配置 ID + 视觉模型名 + 缓存 schema 版本
```

可以把平台配置 ID 与视觉模型名组成稳定的模型选择键，再交给现有 `createImageTranslationCacheKey()`。结果中的 `modelId` 使用同一选择键，确保同一凭据下切换模型不会复用旧缓存。

设置页切换平台或模型时，旧的能力测试结果不得更新新选择的状态；继续使用递增请求 ID 或 AbortController 防止竞态。

## 错误与空状态

- 没有可用平台配置：提示先在“翻译服务”添加并启用 AI 平台、填写 API Key。
- 正在发现模型：禁用视觉模型选择和能力测试，显示加载状态。
- 没有已知视觉模型：提示可刷新；自定义接口不支持发现时提供手动输入。
- 未选择具体模型：禁止开启图片快捷翻译，后台请求也必须失败关闭。
- 已保存模型暂未返回：保留当前值并标注“当前模型未返回”，允许刷新或测试。
- 平台配置被删除或失效：自动清理图片选择并关闭快捷按钮。

## 测试策略

### 纯函数与配置测试

- 平台配置实例过滤、标签生成和重复项编号。
- 视觉模型筛选：支持、未知、明确不支持。
- 老配置补齐 `imageTranslationModelName`。
- 配置删除、禁用、空 API Key 时清理图片选择。
- 文本 `currentModel` 和 `BaseModel.params.modelName` 保持不变。

### 设置页测试

- 选择平台后使用正确的 provider、API Key、官方/自定义地址发现模型。
- 加载、刷新、认证失败、网络失败和手动输入降级。
- 快速切换平台时忽略旧请求结果。
- 选择具体视觉模型后只更新图片配置。
- 支持图片、能力未知及已保存但未返回模型的显示。

### 后台与缓存测试

- 从 `sync:extension-config` 加载配置。
- 请求配置 ID 与当前选择不一致时拒绝执行。
- 使用平台凭据和独立视觉模型名构造内存模型副本。
- API Key、baseUrl 和原始提供商错误不进入响应。
- 同平台配置不同视觉模型生成不同缓存键。
- 老配置迁移后仍能完成图片翻译。

## 验收标准

1. 图片设置第一层能区分翻译服务中同平台的多套配置。
2. 第二层不再显示“百炼”等平台名充当视觉模型，而是显示动态获取的具体模型。
3. 选择视觉模型不会改变文本翻译当前服务或文本模型。
4. 切换视觉模型后图片请求使用新模型且不命中旧模型缓存。
5. 老用户升级后原图片模型选择可自动迁移。
6. API Key 和请求地址不会出现在内容脚本消息或用户可见错误中。
7. 全量检查与生产构建通过。
