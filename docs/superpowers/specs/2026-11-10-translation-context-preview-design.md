# mewCat 智能上下文与段落悬浮提示

用户已确认本次实现以下两个独立需求。

## mewCat 智能上下文

选择内置 mewCat AI 翻译时，可在设置页和快捷面板开启 AI 智能上下文，无需自备模型密钥。扩展从当前翻译会话的原文及网页标题构建至多 2000 个 UTF-16 字符的上下文，随翻译批次发送，后端仅将其作为消歧参考，不翻译上下文本身。关闭时不发送此字段。缓存区分实际上下文；切换开关后更新当前翻译会话。

方案比较：直接发送限长上下文避免额外摘要请求，符合本次需求；先生成摘要需要增加接口、请求次数和延迟，本次不采用。继续沿用 MV3 消息、加密协议、设备身份及现有翻译接口，新增可选 context 字段，已发布旧客户端仍可调用更新后的后端。上下文计入请求字符用量，限制额外资源消耗。后端须先部署，再使用新版扩展的上下文能力；本次只改代码，不部署。

## 段落悬浮提示

基础设置的段落翻译区域增加独立“显示段落悬浮提示”开关，默认 false，旧配置缺失时也是 false。关闭时隐藏高亮框和快捷键文字提示，仍记录鼠标位置以支持段落翻译快捷键。开启后保留现有提示及清理行为；关闭、禁用段落翻译、卸载监听时移除提示，配置即时生效。

方案比较：独立布尔配置符合保留快捷键的需求；使用段落翻译总开关会同时禁用快捷键，故不采用。复用现有 Jotai/Chrome storage 配置持久化，无需额外依赖和权限。

## 验收

- 默认/旧配置不显示段落悬浮提示，快捷键仍有效；开启后显示，关闭后移除。
- mewCat 上下文开关可用，请求中的上下文限长、开关关闭时缺省，批次译文数量保持一致。
- 后端校验可选上下文及长度，旧请求兼容；用量统计包含上下文。
- 上下文缓存隔离及运行时切换有回归覆盖；完成格式化、类型检查、相关测试及构建验证。
