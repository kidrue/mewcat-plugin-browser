# 翻译服务调用留存与用户画像设计

状态：用户已确认设计并授权提交 main 与发布。用户需要行为画像、语言偏好、翻译内容主题与兴趣分析。

## 目标与现状

修改 `apps/service` 中的翻译后端，为后续用户分析保存可追溯的调用事实、翻译内容及聚合结果，并提供可运行的主题分析与画像查询能力。

当前后端为 Fastify + Prisma + SQLite，单进程运行。`Client` 通过签名公钥标识设备，没有账户身份或跨设备关联。`TranslationRequest` 只保存已预占额度的翻译请求、字符数、状态和 token；参数失败、额度拒绝、其他接口调用没有持久化明细；请求记录在 30 天后删除。服务已有定时清理、管理 CLI、真实 SQLite 测试及可注入的供应商请求。

首期使用已验证的 `clientId` 生成设备画像，查询结果明确标记 `identityType: device`。不得用相同 IP、设备名称或客户端自报 userId 合并身份。后续账号体系可通过经过认证的关联表扩展。

只能观察到达本服务的调用。扩展缓存命中、直接请求 Google / Microsoft / 自定义模型的翻译不会进入这些统计；历史记录无法补回过去未保存的语言和内容。`sourceLanguage=auto` 代表请求参数，不冒充实际检测语言。

## 方案比较与建议

1. **同库保存事实，持久化任务异步分析（建议）**：沿用 SQLite，在翻译请求中保存明细和内容；翻译完成后由独立的后台任务提取主题，再更新画像。无需新增基础设施，任务跨重启保留，分析不占用翻译并发槽。
2. **请求内同步生成画像**：结构简单，但分析供应商耗时、超时或限额会拖慢翻译响应，且失败重试容易重复计费，不适合当前翻译接口。
3. **引入消息队列及外部分析平台**：适合多副本和更大数据量，但当前单进程 SQLite 没有对应运维基础，本期收益不足。

建议方案 1。设计批准后才开始产品代码、迁移与实施计划。本期不增加公开管理 API、管理网页、跨设备账号合并或其他翻译平台的客户端埋点。

## 数据模型

所有时间以 UTC 存储。新增字段和表使用兼容性迁移，现有协议、已发布扩展及额度行为保持兼容。

| 数据                      | 主要字段与用途                                                                                                                                                 |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ApiCall`                 | 内部 UUID、服务端 requestId、受控 route/method、可空 clientId、开始/结束时间、HTTP 状态、规范错误码、耗时、可空 translationRequestId；覆盖已知接口的成功及失败 |
| `TranslationRequest` 扩展 | 语言参数、段数、字符数、模型、完成时间、上游耗时、错误码；继续承担预占额度与翻译执行结果记录                                                                   |
| `TranslationContent`      | 与翻译请求一对一；分开保存加密原文数组和可空加密译文数组、加密格式版本、到期时间、规范化原文 HMAC；不把明文复制进任务或画像                                    |
| `AnalysisJob`             | 翻译请求 ID + 分析版本唯一、pending/running/succeeded/failed/expired、attempts、nextAttemptAt、leaseExpiresAt、规范错误码；数据库作为任务队列                  |
| `ContentAnalysis`         | 请求 ID + 分析版本唯一、主题标签、关键词、模型返回置信度、未知类别、生成时间、分析模型和提示词/分类体系版本、分析 token；保留请求级依据引用                    |
| `ClientDailyStat`         | clientId + UTC 日 + route 唯一；请求/成功/失败数、翻译字符数、翻译 token、累计耗时；长期留存                                                                   |
| `ClientLanguageDailyStat` | clientId + UTC 日 + sourceLanguage + targetLanguage 唯一；请求量、字符量、成功量；支持语言偏好及趋势                                                           |
| `ClientTopicDailyStat`    | clientId + UTC 日 + topic + 分析版本唯一；主题样本量与加权得分；重复内容在同一设备同一天只贡献一次                                                             |

为时间清理、设备时间范围查询、任务领取及主题排名建立索引。分析用 token 与翻译 token 分开统计，未知 usage 保留 null，不作为零成本的证明。累计量使用 SQLite 可承载的计数类型，避免 Prisma Int 长期溢出。

## 请求链路与统计口径

1. 在已知路由开始时生成调用上下文；最终响应时保存 `ApiCall`，记录参数错误、401、403、409、429 和供应商失败。公共接口或认证失败的 clientId 为 null，绝不信任未验证的 signerId。未知路径不保存用户提供的 URL、查询字符串或正文。
2. 验证签名后才绑定 clientId；注册成功后绑定实际注册的设备 ID，包括同密钥幂等注册。禁止把 `registration` 当成设备 ID。防重放失败也保留调用事实，但不能再次触发翻译或主题任务。
3. 翻译参数合法、服务有执行槽且额度预占成功时，在同一事务创建翻译执行记录和加密原文。无额度或参数无效时仅记录调用失败，不留存提交内容、不产生分析任务。
4. 翻译成功后在同一事务保存最终执行状态、加密译文及分析任务；失败时保存错误码并为已保存原文创建分析任务，分析主题不依赖翻译成功。响应仍只返回原有译文结构。
5. 翻译执行记录表示供应商调用结果；`ApiCall` 表示 HTTP 接口最终结果。响应加密或发送环节失败时不能把已经成功的供应商结果改成失败。
6. `ApiCall` 与每日行为聚合同事务写入，调用 ID 唯一，重复执行完成逻辑不重复计数。画像区分接口调用次数、已执行翻译数、成功/失败数、被拒绝数。失败响应、并发拒绝和额度拒绝均不伪装成成功翻译。
7. 保存失败时记录规范错误日志并暴露持久化失败计数；不得输出内容。通用调用统计写入失败不能二次发送响应。翻译内容与执行记录的关键写入失败沿用现有服务错误语义，不声称调用一定已留存。

保留“每次 API 尝试”的实际使用频次；只有主题权重对重复内容降权。全站 API 汇总包含无法归属设备的调用。`/health` 和 `/v1/keys` 仅进入调用统计，不进入设备兴趣画像。

## 内容保护与留存

原设计承诺不持久化原文/译文，本次经用户确认的功能会改变这一行为。随实现更新服务文档及可找到的产品隐私说明；上线启用需要同步说明此变化。

- 调用明细默认保留 90 天，原文/译文默认保留 30 天，请求级分析默认保留 90 天；日聚合默认保留 365 天。均可配置。清理按各自到期时间运行，不能因删除短期翻译明细级联删除长期聚合。
- 原文/译文通过专用 32 字节内容密钥做 AES-256-GCM 加密，使用随机 nonce 和带请求 ID/内容类型/格式版本的 AAD；不复用协议签名私钥。密钥从服务环境读取且不得写库。部署时必须备份内容密钥；保留版本字段用于后续轮换。
- 规范化内容使用独立派生的 HMAC 子密钥生成摘要，用于设备内去重；不使用公开可枚举的纯文本哈希。
- 内容采集和后台模型分析分别有明确配置开关。兼容现有部署时默认关闭内容采集和自动分析；启用内容采集必须提供有效内容密钥，否则启动失败。行为明细和行为统计默认启用。用户本次选择的完整功能需要在部署时同时配置并启用这两个开关，查询结果返回实际启用状态与分析覆盖率，避免误认为已收集。
- 内容、主题、关键词不进入普通日志；反馈 message / replyEmail、认证密文、密钥、原始 IP、完整 URL、请求头不作为画像内容保存。保留期过后的任务标记 expired，不继续读取已删除内容。
- 支持管理员按 clientId 删除内容、分析、画像聚合与调用记录；与撤销设备权限分开。清理运行中的分析必须在提交结果时复查数据存在性与删除状态，避免删除后再次生成画像。

保留周期、加密方式和默认开关为本次技术建议，并非用户已经指定的参数。

## 异步主题分析

采用服务端配置的 OpenAI 兼容模型，供应商请求可复用现有配置与请求封装，但使用独立系统提示词、独立输出校验和独立分析并发/预算。分析调用不会改变现有翻译响应协议，也不挤占翻译额度。

- 初始主题为受控枚举：软件开发、人工智能、学术学习、商业工作、产品使用、文娱游戏、旅行生活、其他、未知；关键词数量与长度有上限。枚举及提示词均带版本。
- 输入限制为有界文本样本，记录采样字符数、原字符数和截断标志；原文始终视为数据，不执行其中的指令。禁止输出任意工具调用或用户指令。
- 返回多主题、关键词与置信度；置信度仅为模型自报值。分类不确定时记录未知，不能仅凭一段翻译断言用户职业、年龄或固定身份。兴趣结果表述为“近期翻译内容偏向某主题”。
- worker 默认并发 1，带短轮询和数据库租约；以条件更新领取任务，重启后可恢复过期租约。数据库写事务中不等待模型网络请求，服务关闭时停止领取并中止网络调用。
- 每个请求/版本最多一个结果；结果、任务完成状态与主题日聚合同事务提交，重复任务或重启不重复累加。
- 仅对连接错误、429、超时及临时 5xx 进行退避重试，最多 3 次；输出校验失败记录失败。外部模型不支持幂等时，超时重试可能重复产生供应商费用，因此每次尝试都预占独立分析预算；不能承诺外部调用恰好一次。
- 默认每 UTC 日最多 100 次模型分析尝试、50,000 个输入 UTF-16 单元；任一达到即延后至下一日。预算可配置，持久化跨重启，按尝试计入；不宣称这是精确货币预算。查询可看到 pending / failed / expired 和覆盖率。
- 支持 CLI 限量分析与失败任务重试；使用同一租约、预算、去重和版本逻辑。换版本允许显式重新分析，画像按一个选定版本聚合，不能把多版本重复相加。

## 画像与查询

首期通过管理员 CLI 输出表格或分页 JSON，不新增公开管理端点。

- `analytics summary`：时间范围内接口分布、调用量、成功率、字符/token、平均耗时、活跃设备数、分析队列状态及覆盖率；p95 仅可在调用明细仍覆盖查询区间时准确返回，否则明确不可用。
- `analytics profile <clientId>`：设备注册时间、可用统计范围内首次/最近调用、近 7/30 天活跃天数与调用频率、UTC 活跃时段、常用语言对、常见主题及样本量、平均翻译长度、错误分布、分析版本。短期窗口必须受保留期覆盖信息约束。
- `analytics calls`：按设备、路由、结果、时间过滤的调用明细，游标分页。
- `analytics export`：限时间范围、分页流式导出 JSONL；默认导出结构化统计，内容导出需显式 `--include-content`，正文仅在受控 CLI 解密，不混入日志。支持 `--output` 指定文件并创建受限权限。
- `analytics analyze --limit <n>` / `analytics retry`：显式触发有界分析或重试，受同一预算约束。
- `analytics purge <clientId>`：删除该设备的画像相关数据，输出计数；不清除额度、防重放和客户端密钥，不等同于删除设备身份。

时段与错误分布需要相应的日维度聚合表/受控维度记录，不能只依赖 90 天后已删除的调用明细。实现者可将表拆成 `ClientHourlyDailyStat` / `ClientErrorDailyStat`，或使用有界结构字段；查询性能与原子更新优先。

画像兴趣权重以设备当天不重复内容样本为基础，输出近 30 天主题占比及样本数；成功率和语言偏好使用真实调用次数，不做内容去重。未分析、未知类别和有效分类分别报告；推断不冒充用户自述。

## 修改位置与兼容性

- `apps/service/prisma/schema.prisma` 与新 migration：新增事实、内容、任务及聚合模型，旧字段兼容，已有数据标记元数据未知；迁移不伪造历史主题，不重新发起旧翻译请求。
- `apps/service/src/app.ts`：调用上下文、身份归属、翻译元数据和持久化接入。
- `apps/service/src/store.ts` 及新增 analytics/content/analysis 模块：事务、幂等聚合、内容加密、查询、清理和后台任务。
- `apps/service/src/config.ts`、`src/server.ts`、根 `.env.example`：配置校验、worker 生命周期和独立保留周期。
- `apps/service/scripts/admin.ts` 及新的 CLI 模块：查询、导出、限量分析、重试与删除；复用仓库根 `.env.local` 加载。
- `apps/service/docs/api.md`、服务说明及相关隐私说明：同步保存内容、统计范围和启用步骤。本期不修改公共协议和扩展请求字段，也不处理扩展当前未提交改动。

不部署、不启用线上采集、不运行付费模型请求；实施验收用临时数据库、本地模拟模型和假密钥。完整上线是独立的已配置部署动作。

## 验收

1. 覆盖注册/幂等注册、usage、feedback、translate、公共接口、未授权、重放、额度拒绝、并发拒绝及上游失败，身份和错误归属正确。
2. 翻译原文/译文、主题输入不以明文落入数据库、任务负载或日志；密钥错误和缺失可检测；关闭采集不写内容且查询显示关闭。
3. 同一任务并发领取、超时重启、重复完成及失败重试不重复增加聚合；供应商超时计入分析尝试预算。
4. 模型输出合法性、提示词中的指令文本、空结果、未知主题、采样截断、预算耗尽均有测试。
5. 同内容高频翻译计入行为次数，但在同设备同日不重复放大主题；跨版本不混计；auto 不伪造实际语言。
6. 短期明细与内容清理后，保留期内日聚合仍可查询；任务过期停止分析；设备数据删除与在途分析竞争不会使画像复活。
7. 临时数据库验证从现有 migration 升级；已有记录可读，现有额度、防重放、加密协议及响应测试继续通过。
8. 管理 CLI 的过滤、时间边界、游标分页、导出与内容显式解密有集成测试；无样本和部分覆盖时不输出误导结果。
9. 执行仓库要求的 `pnpm format`，检查差异不包含无关编辑；执行共享包构建、后端 typecheck/test、workspace 检查及 `pnpm build:verify service`。若实际修改扩展或共享协议，则扩大到相应检查。

## 留给实现者的常规决策

模块命名、各聚合维度的具体表拆分、游标编码、内部错误枚举、SQL/Prisma 查询组合及测试夹具可按仓库惯例确定。不得静默改变设备身份范围、内容采集开关、默认保留周期、模型分析预算或对外协议。
