# 图片翻译平台与模型独立选择设计

## 目标

让图片翻译独立于网页文本翻译服务选择模型平台和对应的视觉模型。即使网页文本翻译使用 Google Translate，图片翻译也可以使用任意已配置且具备视觉能力的 AI 模型。

## 可行性与约束

- `BaseModel` 已包含平台 `type`、模型 `id`、启用状态、API Key 和 `capabilities.vision`，现有数据足够构建平台与模型的级联选项。
- 图片翻译运行时已经只传递 `imageTranslationModelId`，后台根据该 ID 解析完整模型配置，因此无需修改消息协议、后台路由或跨域权限。
- 仅展示已启用、API Key 非空并显式声明视觉能力的模型，延续现有安全边界。
- 不修改网页文本翻译的 `currentModel`。

## 交互设计

图片设置页增加两个级联选择框：

1. `模型平台`：只展示至少包含一个可用视觉模型的平台。
2. `视觉模型`：只展示当前所选平台下的可用视觉模型。

已有 `imageTranslationModelId` 时，根据模型反推出平台并展示。没有有效选择时，平台和模型均为空。用户切换平台时，立即把图片模型切换为该平台的第一个可用视觉模型；随后可以在第二个选择框中改选该平台的其他模型。

## 状态设计

继续以 `imageTranslationModelId` 作为唯一持久化状态。平台由当前模型的 `type` 推导，不新增 `imageTranslationPlatform`，也不复用未参与当前运行链路的 `imageTranslateProvider`，避免平台与模型出现不一致或引入迁移。

## 空状态与错误处理

- 没有任何可用视觉模型时，两个选择框都禁用，并提示前往“模型”设置配置支持图片输入的模型。
- 有可用平台但尚未选择模型时，快捷按钮与视觉能力测试保持禁用。
- 当前模型失效时，继续沿用现有修复逻辑关闭图片快捷按钮；不会自动改动文本翻译模型。

## 涉及文件

- `src/utils/visionModels.ts`：提供可用视觉平台、按平台过滤模型、从模型选择推导平台的纯函数。
- `src/options/Image.tsx`：渲染平台/模型级联选择并保存模型 ID。
- `test/vision-models.test.ts`：覆盖平台去重、排序、过滤和选择推导。
- `test/image-settings-ui.test.tsx`：覆盖级联交互、切换平台自动选择首个模型，以及文本模型不变。

## 验收标准

- Google Translate 作为文本翻译服务时，图片翻译仍可独立选择平台和视觉模型。
- 模型下拉只显示所选平台的可用视觉模型。
- 切换平台会保存该平台第一个可用视觉模型的 ID。
- 视觉能力测试和实际图片翻译继续使用 `imageTranslationModelId`。
- `pnpm check` 通过。
