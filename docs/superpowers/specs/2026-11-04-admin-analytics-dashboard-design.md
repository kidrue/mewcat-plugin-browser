# 管理员分析接口与扩展隐藏面板设计

状态：管理员访问范围已由用户确认；完整方案待确认。页面草图只使用明确标注的示例数据。

## 目标与现状

用户需要独立的分析查询接口，并在扩展 options 的“关于”页面单击作者 `kidrue` 后进入分析页面。管理员查看全站数据，可下钻设备画像和调用记录；视觉延续扩展的“晴空来信”主题。

已有后端包含 ApiCall、设备日聚合、语言/时段/错误统计、内容分析及 CLI 查询。已有 JWE/JWS、设备私钥、SDK、防重放和撤销机制。扩展为 WXT + React + styled-components，options 通过 hash 切页；当前只有菜单中的 hash 被接受。作者目前通过 InfoDisplay 以静态文本展示。主题、关键词采集需在服务端启用后才有数据。

## 方案比较与选择

- **建议：复用设备签名，后端配置管理员设备白名单。** 服务端从已验证签名的 clientId 判定管理员，不向扩展打包通用管理密钥；可直接沿用现有协议和设备撤销能力。
- 独立管理口令：便于临时登录其他浏览器，但需增加口令分发、会话和撤销机制，首期不采用。
- 复用扩展账号登录：现有账号 token 与此翻译服务的设备认证尚未关联，需要另建可信身份映射，首期不采用。

采用设备白名单为本次推荐实现选择，用户确认设计时一并确认；用户已明确的是“管理员查看”。

## 访问与授权

服务配置 `ANALYTICS_ADMIN_CLIENT_IDS` 为逗号分隔的设备 UUID，去空白、去重、最多 20 个；默认为空，即不允许任何设备查询管理员数据。仅服务端读取，禁止导出为 WXT*/VITE* 变量。

用户单击作者后，后台复用已经持久化的 SDK 身份；首次使用时按现有流程注册和保存。页面只接收本设备 clientId 与服务地址，不获取私钥、服务器秘密或完整 SDK state。未授权时展示“当前设备尚未获得管理员权限”、完整可复制的本机设备 ID、“重新检查”和“返回关于”。服务管理员将该 ID 加入生产白名单后重新部署，页面重试即可使用；不得由页面自行申请通过或写白名单。

每次查询均验证签名、时间、nonce 和设备撤销状态，再判定白名单。非管理员统一返回加密的 `403 ANALYTICS_FORBIDDEN`，不泄漏数据、其他设备是否存在或查询参数校验细节。撤销设备即失去访问能力，移除白名单后立即对新请求生效（静态环境配置需重启/部署）。清除浏览器数据或换设备后需要重新授权。

首期只读，页面及分析接口不提供清除数据、撤销用户、调整额度、触发付费分析或导出原文/译文。

## 独立接口

新增 `POST /v1/analytics/query`，请求体沿用 `{ envelope: "..." }`，响应也签名加密。共享协议增加严格的 discriminated union 和响应 schema，旧翻译、usage、feedback 请求/响应不变。

| operation  | 参数                                                                 | 主要返回                                                                                                                   |
| ---------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `overview` | `from`, `to`                                                         | 翻译请求、成功/失败、字符、已知 token、活跃翻译设备、平均/p95 耗时、每日趋势、语言及错误分布、采集和分析状态、数据覆盖说明 |
| `devices`  | `from`, `to`, 可选完整 `clientId`、`cursor`、`limit`                 | 时间范围内有业务调用的设备、注册/撤销状态、活跃情况、调用/翻译字符量及下一页游标                                           |
| `profile`  | 完整 `clientId`                                                      | 当前设备近 7/30 天行为、语言、UTC 活跃时段、错误、主题、关键词、分析样本及覆盖率                                           |
| `calls`    | `from`, `to`, 可选 `clientId`, `route`, `outcome`, `cursor`, `limit` | 调用明细、翻译执行元数据、结构化分析结果及下一页游标                                                                       |

时间字段使用 `YYYY-MM-DD`，左闭右开 UTC 日区间，校验真实日期、顺序及最多 90 天。前端结束日选择为包含当日，在请求时转换为次日 UTC 零点。首次默认近 7 个 UTC 日，可切换近 30 日或自定义。图表注明 UTC 日界对应北京时间 08:00，明细时间按浏览器时区展示。

`profile` 延续已有近 7/30 天口径，不接受全局日期参数；设备抽屉明确标注“近 30 天画像”。其他操作不接受无效或未使用的参数。设备 ID 只支持精确匹配，首期不增加模糊搜索。分页默认 20、最多 100，游标为校验过的复合键；更改筛选条件后前端清空游标。

大整数以十进制字符串返回，避免 Number 精度丢失；比例和耗时为有界有限数或 null。图表对大整数做比例缩放，标签保留精确格式化值。单次响应目标不超过 256 KiB；语言/错误/关键词显示有界 Top 列表，不一次加载全部设备或调用。

查询有独立的每管理员设备每分钟 60 次限制及单进程最多 2 个执行中的分析查询，不扣翻译日额度或触发模型。频率超限返回 `429 RATE_LIMITED`，并发满返回 `503 ANALYTICS_BUSY`。参数与权限检查在重查询之前完成。后台模块关闭/请求取消后释放查询槽，不把取消解释为查询成功。

## 数据口径与查询扩展

全站概览的主要数字标注为“翻译调用”，限定 `/v1/translate`，不把健康检查、公钥获取或管理员查询算作翻译使用量。活跃翻译设备同样按该路由的已验证 clientId 去重。错误分布来自该路由的最终 HTTP 结果；语言分布来自已执行翻译，因此拒绝请求可能没有语言信息。

每日趋势复用 `AnalyticsDaily` 的 route 维度，补齐有数据覆盖范围内的空日期；未采集的历史区间显示覆盖不足，不冒充零使用量。扩展 `AnalyticsQuery.summary` 的可选路由筛选，保留现有 CLI 默认行为；同时扩展每日趋势、设备分页及有界分布查询。最多 90 天的调用错误查询用事实表，适用时增加 `(route, createdAt, id)` 索引；缺失历史元数据不回填伪造数据。

设备列表和画像使用已有业务行为口径，明确其调用量可能包含注册、usage 和 feedback；调用明细可按路由和结果筛选。所有响应返回 `asOf` 和实际数据覆盖信息，不承诺多个独立请求间的事务快照。token 只汇总供应商报告的值，不将未知 usage 当作精确零费用；p95 无有效样本或明细覆盖不足时显示不可用。

管理员查询不加入用户使用画像与常规业务统计，避免页面刷新自我增加用量。认证失败/越权/查询失败按既有规范日志记错误码和 requestId，不记录查询响应或画像正文。设备列表和调用响应采用字段白名单，不返回设备公钥、nonce、原始 IP、密文、原文、译文或秘密配置。

采集关闭时行为图表仍可展示，内容模块显示“内容采集未启用”；采集开启但分析关闭时显示“自动分析未启用”；尚未完成分析时显示待处理/失败/到期数量。没有主题样本时不用示例主题补空。

## 扩展入口和数据链路

单击作者 `kidrue`（原位的语义 button，支持 Enter/Space 和可见焦点）进入 `options.html#analytics`。不新增 NAVIGATION_ITEMS，侧边栏保持“关于”选中；分析页提供返回关于按钮。hash 解析显式允许 analytics，浏览器刷新及前进/后退都能恢复该页，其余未知 hash 仍按原规则回退。

页面通过专用 `analytics-query` 消息向 background 请求；本设备信息通过独立的 `analytics-identity` 消息取得。后台检查 sender.id 等于本扩展且 sender.url 的基础地址是本扩展 options.html，拒绝网页、content script、popup 和 feedback 页发起该通道。不要仅以 hash 作为权限凭据。

background 调用 `mewCatService.queryAnalytics`，复用初始化中的 SDK 实例；共享客户端增加 `queryAnalytics` 方法并更新导出的类型。请求超时、取消、接口未上线、401/403、429/503 均返回受控状态，不进入通用 Sentry 采集正文的路径。页面不持久化分析响应，退出时清空数据；更改筛选条件时取消旧请求或用请求标识忽略过期响应。

## 页面设计

延续现有主题 token：浅蓝页面、白色纸面、天空蓝强调色、12–16px 圆角、20–24px 内容间距；中文用寒蝉全圆体，数字/设备 ID/耗时用等宽。直接复用 OptionsPageIntro、OptionsSection、OptionsCardGrid、按钮及 SkyArtwork 的 archive/ledger 素材，不新增插画或图表依赖。

页面由紧凑插画页头、“概览 / 设备画像 / 调用记录”三个内部视图组成。顶部有返回关于、日期范围、刷新与最近更新时间。首次进入查询一次，后续手动刷新；首期不自动轮询，避免增加生产查询负担。

- 概览：4 个关键数字块（翻译调用、成功率、翻译字符、活跃翻译设备），调用/字符趋势；语言与错误分布；token、平均/p95 耗时作为次级指标；内容采集与分析覆盖状态放在独立分组。
- 设备画像：有界分页列表，显示名称、短 ID、调用和字符、活跃时间、状态；单击设备查看详情抽屉，提供复制完整 ID 和转到该设备调用记录。
- 调用记录：日期、完整设备 ID、接口、成功/失败/被拒绝过滤；表格展示时间、设备、路由、状态、错误码、字符、token 和耗时；展开只显示受控元数据及主题分析结果。

宽屏用有主次双列，窄屏数字块变两列/单列，图表纵向排列；表格独立横向滚动，抽屉变全宽。蓝色系列保持一致，失败使用现有珊瑚红语义色；不依靠颜色单独表达状态。SVG 图表提供文字摘要及数据表/标签，遵守 reduced-motion。

必须有首次加载骨架、后台刷新状态、无记录、未授权、接口未部署、网络错误、筛选无结果、采集/分析关闭和明细覆盖不足状态。刷新错误不把旧数据标记为最新，保留旧数据时明确显示更新时间及错误。网络失败不得显示模拟数据。

## 修改位置

- `apps/service/src/analytics/`：管理员查询投影、聚合与路由模块；`src/app.ts`、`config.ts` 接入；必要的 Prisma 索引 migration。
- `packages/mewcat-protocol/src/`：分析请求/响应 schema 和类型；`packages/mewcat-client/src/`：SDK 方法与导出类型。
- `apps/extension/src/options/About.tsx`、`options/index.tsx`：隐藏入口和 hash；新增 `options/Analytics.tsx`、`analytics/` 下的请求状态、图表和视图组件。
- `apps/extension/src/background/messages/`、`background/lib/mewcat-service.ts`、`messaging/protocol.ts`：只允许 options 的消息通道和 SDK 调用；`services/analytics.ts`：页面消息封装。
- 根 `.env.example`、后端运行时配置更新器、两个发布工作流及说明：管理员白名单的验证、显式传递与原值保留；不把当前浏览器擅自设为管理员。
- 生产入口仍为 `kidrue/mewCat-servicer`，需兼容同步后端与独立 client/contracts；monorepo 后端部署开关继续遵循现有切换规则。

## 验收

真实 SQLite + 签名链路验证管理员可查、非管理员/撤销设备/伪造身份不可查、防重放、限流、查询槽恢复及非法筛选。确认不泄漏正文/密钥、不扣翻译额度、不把管理员读取计入画像；测试时间边界、分页、零/未知数据、BigInt、覆盖不足和过期响应。

扩展测试覆盖单击作者、键盘进入、hash 刷新/返回、菜单未新增、sender 来源拒绝、未授权 ID 展示、日期筛选、设备下钻、分页及错误状态。草图为纯示例数据，正式验收使用受控服务响应，禁止用生产付费模型做测试。

执行 pnpm format、共享包构建、后端检查、相关扩展测试、扩展 typecheck/lint 与 build:verify；在浏览器检查宽屏、390px 窄屏、焦点和真实资源。用户确认本设计后进入实施计划，不重复询问常规编码/验证步骤；上线管理员设备授权需根据用户实际设备 ID 进行。
