# mewCat 减法与性能优化计划

先清理可验证的重复实现，再根据真实浏览器测量选择性能改动。每项改动独立验收，保持现有功能入口、默认行为、失败处理、升级兼容、MV3 权限和客户端协议。

## 待完成的维护工作

### 记录基线

- [ ] 用现有示例页和模拟响应，在真实浏览器中补验首次安装、已有配置升级、并发保存、网页与 iframe 翻译、段落补译、划词、图片及总结。对照候选和译文顺序、导航和取消、关闭还原、缓存命中及迟到响应，改动前后使用同一夹具。浏览器复验见 [扩展测试说明](../../../apps/extension/test/README.md)。

## 性能候选

- [ ] 用当前生产构建记录 Manifest 全站脚本、按需脚本及相关资源的原始大小。早期 1.1.13 的包体积仅用于历史对照。
- [ ] 用同版 Chrome、固定机器和模拟翻译响应，在空闲页面、长文首次翻译、持续变更和滚动场景各预热后重复至少五次。记录 CPU 和单批耗时中位数、候选数、mutation 批次、全页提取数、几何读取、请求量和首批译文时间。
- [ ] 根据 Trace 核对 `initialize.content.tsx`、语言检测和配置首次写入的时序。仅在生命周期、并发写入和失效条件等价时调整非可见 UI 初始化或重复检测。
- [ ] 根据 Trace 检查 DOM 扫描、几何读取和调度排序中的重复工作。缓存等待和实际发请求前继续核验位置、节点和会话。用快速滚动、内部滚动容器、SPA 节点替换、iframe、GitHub、段落和换行回归对照收益。
- [ ] 页面总结按需加载、设置页标签懒加载、CI 重复构建及模型设置职责收拢，在测得代价后再立项。服务端画像可先用合成 SQLite 数据比较 `profile()` 的重复汇总查询，复验留存、p95 和取消语义。
